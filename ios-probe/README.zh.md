# RouteForge 最小苹果测试 App

这是自有 iOS 定位原型的本地源代码，独立于现有安卓模块。**尚未通过 Xcode 编译或在手机安装验收，不是已经可用的 IPA。** 现成 StikDebug 的 10 分钟实测只作为它的验收基线。

## 首版范围

- 中文界面、导入本机 RPPairing 文件、通过 LocalDevVPN 连接本机。
- 定点、GPX/XML/双列坐标文本导入、合成示例环线、速度设置。
- 默认每 5 秒更新，默认本轮最多 10 分钟。路线完成、时限达到或更新失败后尝试清除模拟位置。
- 主动停止支持在旧流清除失败后重建连接再清除；失败会保留恢复提示，不显示“已恢复真实位置”。
- 真实位置恢复由用户在高德核对后确认。上次会话未确认恢复时，下次启动会保留恢复入口。
- 本 App 前台模拟时常亮，停止后恢复系统空闲计时器。切到高德后的常亮不由本 App 保证；锁屏不列入当前验收。
- 后台维持使用系统音频和低精度定位能力，真实位置不进入日志。这一实现仍需在自有 App 真机复验。

暂不包含道路规划、离线路网、收藏、地图选点和安卓全部功能。导入文件统一允许数据类型，再验证内容，避免先前工具中 GPX 文件不可选的问题。

## 开发与打包

项目要求 macOS、Xcode、Python 3.11+ 与 XcodeGen。运行 `bash scripts/build.sh`：校验下载固定版本依赖、执行轨迹核心测试、生成 Xcode 工程、编译并输出 `build/RouteForgeProbe-unsigned.ipa`。后续在 Windows 使用现有 iloader 账号由用户签名安装。

Windows 可以准备源代码、检查配置及依赖，Xcode 编译使用 macOS。配套 GitHub Actions 只支持手动触发，按用户明确上传授权执行构建；编译产物下载后在 Windows 本地签名，不向云端提供手机配对文件或 Apple ID 登录资料。

本地已完成 Swift/C 语法解析、项目 YAML / Info.plist / 构建脚本检查、依赖摘要校验，以及所调用 13 个底层函数的 arm64 库导出符号检查。核心模块 7 项单元测试已在 macOS 云端全部通过；App 的 Xcode 打包及真机验收仍在推进，不能仅以单元测试通过视为手机端通过。

## 手机初次配置

1. 保留已开启的开发者模式，完成现有开发者映像初始化。这一最小版尚未自动下载或挂载开发者映像；重启后若服务未就绪，需要先通过已验证的电脑工具或 StikDebug 初始化。
2. 打开 LocalDevVPN，按已验证的 Wi-Fi 条件连接。
3. 在“轨迹测试”导入已生成的本机配对文件。可从手机“文件”App 的 StikDebug 目录选择 `pairingFile.plist`；不将其提交仓库或放进安装包。
4. 默认端口 49152；需要时查找 Bonjour 服务并选择本机端口，也可填写 StikDebug 显示的端口。连接始终指向本机 VPN 地址 `10.7.0.1`。
5. 先测定点，再测示例环线；切到高德核对蓝色当前位置。拔线、亮屏、10 分钟和停止恢复的验收条件沿用已通过的参考工具基线。
